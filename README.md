# Hardware Implementation of Neuron Types for Neural Networks

This repository contains the source code for my Bachelor's thesis. While the written thesis is in Hungarian, this repository and documentation are maintained in English.

## Abstract

The aim of this thesis is the efficient hardware implementation of neural networks and their various activation functions on FPGA, as well as the examination and comparison of these implementations. The significance of the topic is justified, on the one hand, by the increasing computational demands of modern machine learning models, and on the other hand, by the low latency and energy efficiency of FPGAs, which make them ideal for real-time applications. During the research, I implemented and analyzed various approximation techniques—including piecewise constant and piecewise linear approximations—in a High-Level Synthesis environment, using FPGA-oriented fixed-point quantization. The investigations were based on simple, pixel-based classification networks trained using PyTorch, which were reproduced in hardware form.

Based on the results, the ReLU activation proved to have the lowest resource requirements, while functions requiring floating-point operations showed significant latency and resource consumption. The LUT-based solutions did not perform sufficiently well due to quantization characteristics; in contrast, the PWC (piecewise constant) approximation provided the best compromise between accuracy and hardware efficiency. The thesis points out that by applying appropriate approximation techniques, significant performance and resource savings can be achieved in FPGA-based neural networks.

During the investigations, I analyzed in detail the latency of each implementation, the amount of logic resources used, and the accuracy loss caused by quantization. I also presented the effects of HLS optimizations—such as pipeline, unroll, or array partition—and demonstrated that with the use of appropriate pragmas, execution time can be further reduced and throughput efficiency can be increased. The hardware results were compared with software reference models, allowing the discrepancy in numerical behavior and performance to be measured precisely. An important takeaway of my thesis is that the combination of well-chosen fixed-point quantization and minimal-resource approximation functions allows for the design of neural networks that are energy-efficient, fast, and adequately accurate. The results of the thesis create a foundation for future FPGA-based implementations of larger and more complex networks, as well as for the optimized hardware implementation of additional neural components, such as convolutional layers or normalization blocks.

## Overview & Workflow

The pipeline is split into Python model training/quantization and AMD Vitis High-Level Synthesis (HLS) hardware implementation.

### 1. Python Notebooks

* **`01_train_nn_save_weights.ipynb`**  
  Demonstrates training a simple neural network, applying quantization, and exporting the trained weights, biases, and scaling factors.
* **`02_define_act_functions.ipynb`**  
  Demonstrates custom activation function implementations and exports activation-related parameters (including lookup tables where applicable).

---

### 2. HLS Implementation (`/hls_neural_network/hls_implementation`)

This directory contains the C/C++ source files required for AMD Vitis HLS synthesis and simulation.

#### Vitis Project Setup:
* **Synthesis Sources (`Source` directory):**  
  Include all `.cpp` and `.h` files **except** `neural_network_tb.cpp`.
* **Testbench Sources (`Test Bench` directory):**  
  Add `neural_network_tb.cpp`, `val_dataset_X.txt` and `val_dataset_Y.txt`. 
* **Generated Data Files:**  
  Place the weights, biases, scaling factors, and lookup tables generated by the Python scripts into your project directory.

#### Path Configuration:
Update the relative or absolute file paths for model parameters and lookup tables in the following header files:
* `read_data.h` — Weights, biases, and scaling factors.
* `activations.h` — Lookup table (LUT) data for activation functions (if using LUT-based implementations).
